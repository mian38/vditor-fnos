## 本版本要点（供回溯参考）

1.1.3 相对 1.1.2 的主要变化：

- **修复「上传限制放开 + 可调」未生效**：根因是 Vditor 的 `upload.accept` **没有「不限制」状态**
  （校验为 `accept && accept.split(",").some(t => t[0]==="." ? ext===t : mimeTop===t)`，无 `*` 分支，
  `'*'` 与 `''` 都会拦掉全部上传）。改用 `VDITOR_ACCEPT_ANY` 短路前端校验，格式判定收归服务端。
- 上传格式由**白名单反转为黑名单**（`upload_deny`），默认 67 项高风险扩展名，可逐条增删。
- 上传黑名单输入控件与同页其它输入控件**统一样式**（并入通用输入框选择器组 + chip 形式）。
- 预留手机App 接口规范 `docs/MOBILE_API.md`（仅规范，无路由挂载）。

## 已知问题（本版本存在，1.1.4 已修）

1. **黑名单行按钮与输入框错位**：`.set-sec button.action { margin: 10px 8px 0 0 }`（特异性 0,2,1）
   压过了 `.set-ext-row button { margin: 0 }`（0,1,1），导致「添加 / 恢复默认」整体下沉约 10px。
2. **「恢复默认」后无法保存**：默认清单含 `appref-ms`（含连字符），而扩展名校验器
   `_EXT_TOKEN_RE` / `denyTokenValid` 仅允许字母数字，故该项被判非法 → 整次保存被拒。
   同时 `UPLOAD_NAME_RE` 亦不接受连字符，含连字符的扩展名落盘后会取不到（404）。

> 回滚到本快照即会一并恢复上述三个问题。
